# Peek — больше контекста в списке диалогов ВК

## Проблема

В списке диалогов на https://vk.ru/im видно только последнее сообщение, обрезанное до одной
строки. Чтобы понять, о чём речь, приходится заходить в каждый диалог. Для человека, который
переписывается по работе, это десятки лишних кликов в день.

## Решение

Браузерное расширение, которое разворачивает превью прямо в списке: больше строк текста
и несколько последних сообщений вместо одного.

Никакого бэкенда и никакого аккаунта. Всё локально в браузере, настройки в `chrome.storage.sync`.

## Этап 1 (текущий)

Два независимых параметра отображения, оба настраиваются в попапе расширения:

- **Строк** — сколько строк текста показывать в превью. Диапазон 1–10, по умолчанию **5**.
  Потолок считается на каждое сообщение, а не на весь блок превью.
- **Сообщений** — сколько последних сообщений диалога показывать. Диапазон 1–5,
  по умолчанию **2**. При значении 1 поведение как у ВК, только строк больше.

Плюс общий тумблер «включено», чтобы можно было быстро вернуть штатный вид.

Область работы: список всех диалогов на https://vk.ru/im. Только он, в сам диалог заходить не надо.

### Как это устроено

1. **Строки.** Контент-скрипт находит в строке диалога элемент превью и снимает с него обрезку
   (`-webkit-line-clamp`, `white-space: nowrap`, фиксированную высоту у родителей), подставляя
   свой лимит строк. Элемент ищется не по классам ВК, а по вычисленным стилям: берём тот, который
   реально обрезан. Так правка переживает редизайн вёрстки.
2. **Сообщения.** Одного DOM мало: ВК отдаёт в список только последнее сообщение. Остальные
   дотягиваем через внутренний API — токен снимаем из запросов самого веб-клиента к `api.vk.com`,
   истории запрашиваем пачкой через `execute` (до 25 диалогов за один запрос) и кладём в кэш.
   Запрос истории не помечает сообщения прочитанными.

### Чего не делаем на этапе 1

- Никаких чатов, кроме списка на `/im`. Мини-мессенджер в шапке и сообщения сообществ — потом,
  если попросят.
- Никакой синхронизации настроек через свой сервер. Хватит `chrome.storage.sync`.
- Никакой отправки чего-либо наружу. Токен не покидает браузер.

## Этап 2 (запланировано, не делаем сейчас)

**Быстрый ответ из списка диалогов.** Поле ввода прямо в строке диалога, чтобы ответить,
не открывая переписку.

Что нужно продумать, когда дойдём:

- Куда встраивать поле: разворачивать по клику на иконку в строке или показывать всегда
  у первых N диалогов. Скорее первое, иначе список превратится в кашу.
- Отправка через `messages.send` тем же перехваченным токеном. Нужен `random_id`, чтобы
  повторный клик не задваивал сообщение.
- Оптимистичный рендер: сообщение появляется в превью сразу, при ошибке откатывается
  с понятным текстом.
- Enter отправляет, Shift+Enter переносит строку. Escape закрывает поле.
- Отметка о прочтении: отвечая из списка, человек фактически прочитал диалог. Решить,
  дёргать ли `messages.markAsRead`, и спросить об этом в настройках.
- Вложения и эмодзи в первой версии не нужны, только текст.

## Распространение

- Лендинг на GitHub Pages: что делает, скриншот, кнопка «Скачать» и инструкция по установке
  распакованного расширения через `chrome://extensions`.
- Публикация в Chrome Web Store — отдельным шагом. Нужен аккаунт разработчика, разовые $5
  и модерация. До неё лендинг остаётся основным способом установки.

## Риски

- **Вёрстка ВК меняется.** Лечится тем, что превью ищем по стилям, а не по классам, плюс
  расширение молча выключается, если ничего не нашли, и не ломает страницу.
- **Виртуализированный список.** Если ВК считает высоту строк заранее, увеличение высоты
  поедет. Проверяется только на живой странице.
- **Лимиты API.** 3 запроса в секунду на токен. Поэтому `execute` пачками и кэш, а не запрос
  на каждый диалог.
