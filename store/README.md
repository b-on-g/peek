## Вкладка «Описание»

**Название**

```
Peek — больше строк в списке диалогов ВК
```

**Краткое описание** (до 132 символов)

```
Разворачивает превью в списке диалогов ВКонтакте: больше строк текста и несколько последних сообщений вместо одной строки.
```

**Подробное описание**

```
ВКонтакте показывает в списке диалогов одну обрезанную строку последнего сообщения. Чтобы понять, о чём речь, приходится заходить в каждый диалог по очереди.

Peek разворачивает превью прямо в списке.

• Больше строк. От одной до десяти, по умолчанию пять. Длинное сообщение видно целиком, не открывая переписку.
• Несколько последних сообщений. От одного до пяти, по умолчанию два. Видно, чем закончился разговор и кто написал последним.
• Тумблер. Одно нажатие возвращает штатный вид ВКонтакте, удалять расширение не нужно.

Настройки меняются в один клик по иконке и применяются сразу, страницу перезагружать не нужно.

Работает на vk.ru и vk.com, в списке всех диалогов.

Что с данными: у расширения нет сервера, нет аккаунтов и нет аналитики. Оно ничего никуда не отправляет. Прошлые сообщения запрашиваются у API ВКонтакте тем же способом, каким это делает сам сайт в вашей вкладке, и дальше вкладки не уходят. Настройки хранятся в браузере.

Исходный код открыт: https://github.com/b-on-g/peek
```

**Категория:** Рабочие процессы и планирование (Workflow & Planning)

**Язык:** русский

## Вкладка «Конфиденциальность»

**Единственное назначение** (single purpose)

```
Peek показывает больше текста в списке диалогов ВКонтакте.

ВКонтакте выводит в списке только одну обрезанную строку последнего сообщения, из-за чего, чтобы понять, о чём диалог, приходится открывать его целиком. Расширение снимает с превью ограничение по высоте и показывает столько строк, сколько выбрал пользователь, а по желанию — ещё и несколько последних сообщений диалога вместо одного.

Больше расширение не делает ничего: оно не меняет другие страницы, не добавляет кнопок и элементов интерфейса, не отправляет сообщений от имени пользователя, не показывает рекламу и не собирает статистику. Работает только в списке диалогов на vk.ru и vk.com.
```

**Обоснование разрешения `storage`**

```
В chrome.storage.sync хранятся только настройки самого расширения: включено оно или нет, сколько строк показывать в одном сообщении (от 1 до 10) и сколько последних сообщений выводить (от 1 до 5). Синхронизируемое хранилище выбрано, чтобы пользователю не приходилось задавать эти три значения заново после перезапуска браузера и на каждом устройстве.

В chrome.storage.session на время сессии кладётся токен доступа ВКонтакте, необходимый для запроса последних сообщений. Сессионное хранилище выбрано специально: токен стирается при закрытии браузера и не попадает на диск.

Тексты сообщений, списки контактов и любые другие пользовательские данные в хранилище не записываются.
```

**Обоснование доступа к сайтам (host permissions)**

```
Расширение работает исключительно на ВКонтакте, поэтому запрошены только домены самого сервиса.

*://vk.ru/*, *://*.vk.ru/*, *://vk.com/*, *://*.vk.com/* — контент-скрипт встраивается в страницу списка диалогов (/im), находит элемент превью и снимает с него ограничение по количеству строк. Это и есть основная функция расширения, без доступа к этим доменам она невозможна. Шаблоны с поддоменами нужны потому, что мессенджер ВКонтакте работает и на основном домене, и на поддоменах сервиса.

https://api.vk.com/* и адрес web.api.vk.ru, попадающий под *://*.vk.ru/* — API ВКонтакте. К нему расширение обращается методом messages.getHistory, чтобы получить несколько последних сообщений диалога, когда пользователь включил такой режим. Запрос идёт тем же способом и на тот же адрес, которым пользуется сам сайт ВКонтакте в открытой вкладке пользователя.

Никаких других доменов расширение не запрашивает и никуда, кроме API ВКонтакте, данные не передаёт.
```

**Обоснование удалённого кода** (remote code)

Выбрать «Нет, я не использую разрешение "Удаленный код"». Если поле обоснования появится:

```
Весь исполняемый код входит в пакет расширения. Скрипты с внешних адресов не загружаются, eval и new Function не используются.
```

**Какие данные собираются**

Отметить два пункта, остальные оставить пустыми:

- ✅ **Аутентификационные данные** — расширение считывает токен доступа из запросов, которые страница ВКонтакте отправляет сама, и использует его только для обращения к API ВКонтакте. Токен лежит в памяти сессии и стирается при закрытии браузера.
- ✅ **Личные сообщения** — расширение читает текст последних сообщений, чтобы показать их в списке. Тексты живут в памяти открытой вкладки и никуда не отправляются.

Не отмечать: сведения о личности, состояние здоровья, финансы, местоположение, история посещений, действия пользователя, содержимое сайтов.

Про «Содержимое сайтов» отдельно: со страницы расширение читает ровно один фрагмент — текст превью, а это сообщение из чата, уже покрытое пунктом «Личная коммуникация». Лишняя галочка добавит на карточку пугающую строку, не добавив точности.

**Три обязательные галочки** — для этого расширения все три верны:

1. Не продаю и не передаю данные третьим лицам вне утверждённых случаев.
2. Не использую и не передаю данные для целей, не связанных с назначением расширения.
3. Не использую и не передаю данные для оценки кредитоспособности или выдачи займов.

## Публикация

Видимость: **общедоступное** (Public). Регионы: все.

## Чего ждать от ревью

Заявка содержит доступ к личным сообщениям и к токену — на такое смотрят внимательнее обычного, первая проверка может занять несколько дней вместо часов. Если попросят сузить разрешения, самый быстрый ответ — выпустить версию только с разворачиванием строк, без обращения к API: это отдельная сборка без `inject.js`, `background.js` и доступа к API.
